# 데이터베이스 및 보안 명세

## 1. 저장 정책

Supabase는 선택 동의 기반 분석 기록 저장에만 사용한다. 동의하지 않은
분석은 DB에 저장하지 않는다. 계정 기능은 MVP 범위 밖이므로 저장 데이터에
사용자 계정이 있다고 가정하지 않는다.

## 2. 테이블 제안: `sentiment_analyses`

  컬럼         타입          규칙
  ------------ ------------- ----------------------------------
  id           uuid          기본키, `gen_random_uuid()`
  sentiment    text          positive/negative/neutral만 허용
  confidence   int2          0\~100
  reason       text          최대 500자
  input_text   text          최대 2,000자
  created_at   timestamptz   기본 now()

저장 기능이 실제 구현되기 전 SQL 마이그레이션 파일을 만들고 검토한다.
입력 원문은 민감한 내용일 수 있으므로 저장 기간과 삭제 정책을 서비스
공개 전에 확정한다. MVP 기본 제안은 30일 후 자동 삭제이며, 자동 삭제
작업이 실제 구성되지 않았다면 해당 정책을 구현했다고 주장하지 않는다.

## 3. 접근 통제

-   RLS를 활성화한다.
-   브라우저에서 테이블을 직접 조회/삽입하지 않는다.
-   서버에서만 `SUPABASE_SERVICE_ROLE_KEY`를 사용한다.
-   서비스 키는 절대 `public/`, Git, 브라우저 응답에 포함하지 않는다.
-   공개 anon 키를 사용하더라도 정책 없이 테이블 접근을 열지 않는다.
-   테이블에 공개 SELECT/INSERT 정책을 만들지 않는다.
-   서버리스 함수에서 입력값을 검증한 뒤 최소 필드만 저장한다.

## 4. 개인정보와 로그

-   동의 기본값은 false.
-   동의 문구는 저장 대상(입력 텍스트와 분석 결과)을 구체적으로
    안내한다.
-   저장 동의는 분석 동의와 분리한다.
-   기본 로그에는 원문 텍스트를 기록하지 않는다.
-   데이터 보유기간·삭제 절차·개인정보 처리방침은 실제 공개 전에
    운영자가 확정한다.

## 5. 필수 환경변수

``` env
OPENAI_API_KEY=
OPENAI_MODEL=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

`SUPABASE_*`는 저장 기능 사용 시에만 필요하다. 값이 누락된 경우 저장
기능은 비활성화하거나 저장 실패 상태를 명확히 처리한다. 분석 자체는
OpenAI 설정이 정상이라면 계속 가능해야 한다.

## 6. 보안 검증

-   저장 동의 false인 요청에서 DB insert가 실행되지 않는지 확인한다.
-   브라우저 개발자 도구에서 서비스 키가 보이지 않는지 확인한다.
-   RLS가 켜져 있고 익명 브라우저 요청으로 테이블 접근이 거부되는지
    확인한다.
-   XSS 문자열 입력 시 실행되지 않고 텍스트로 표시되는지 확인한다.
-   입력 크기 제한, 요청 제한, 오류 메시지 비노출을 확인한다.
