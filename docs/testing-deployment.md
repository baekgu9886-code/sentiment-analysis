# 테스트, 완료 기준 및 Vercel 배포

## 1. 테스트 환경

-   로컬 Node.js LTS
-   별도 테스트용 OpenAI 키 및 Supabase 프로젝트 권장
-   실제 비밀키는 테스트 문서나 Git에 기록하지 않는다.
-   자동 테스트와 수동 UI 테스트를 구분해 결과를 보고한다.

## 3. UI/접근성 테스트

-   360px, 768px, 1440px 화면에서 확인한다.
-   가로 스크롤이 없어야 한다.
-   Tab/Shift+Tab/Enter/Space로 주요 기능을 조작한다.
-   포커스 표시가 보인다.
-   textarea와 체크박스에 명시적 label이 있다.
-   로딩·오류·결과가 스크린리더에 전달된다.
-   색상 외에도 긍정/부정/중립 텍스트가 표시된다.

## 4. 배포 전 체크리스트

-   [ ] `.env`가 `.gitignore`에 포함되어 있다.
-   [ ] `.env.example`에는 키 값이 비어 있다.
-   [ ] OpenAI 키를 서버 환경변수로 등록했다.
-   [ ] Supabase 사용 시 URL과 service role key를 서버 환경변수로
    등록했다.
-   [ ] Supabase RLS 및 테이블 제약을 확인했다.
-   [ ] Vercel 프로젝트의 Root Directory와 빌드 설정을 확인했다.
-   [ ] API 함수가 Vercel 런타임에서 동작한다.
-   [ ] Preview 환경에서 기능 테스트를 통과했다.
-   [ ] Production 환경에 별도 환경변수를 등록했다.
-   [ ] 실제 도메인에서 모바일·데스크톱 테스트를 수행했다.

## 5. Vercel 배포 원칙

-   정적 파일은 `public/`에서 제공한다.
-   `api/`는 Vercel Functions로 배포한다.
-   별도의 상시 실행 Node 서버를 요구하지 않는다.
-   프로젝트 설정은 현재 Vercel 공식 문서와 실제 생성된 프로젝트 구조를
    기준으로 한다.
-   환경변수 추가·수정 후 재배포가 필요한지 확인한다.
-   배포 성공 화면만으로 기능 검증 완료라고 판단하지 않는다.

## 6. 완료 판정

MVP 완료는 아래 조건을 모두 만족할 때만 선언한다. 1. PRD의 필수 기능
FR-01\~FR-05가 작동한다. 2. 선택 저장 기능은 동의 여부에 따라 올바르게
동작한다. 3. 필수 테스트 T-01\~T-13 결과가 기록되어 있다. 4.
반응형·접근성 기준을 충족한다. 5. 비밀키 노출 및 공개 DB 접근 취약점이
없다. 6. Vercel Preview 또는 Production에서 실제 API 요청이 성공한다. 7.
미해결 문제와 제한사항이 문서화되어 있다.
