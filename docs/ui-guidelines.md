# UI 구현 지침

## 1. 참고 이미지 해석

사용자가 첨부한 Magnific 메인 화면을 시각적 참고 자료로 사용한다. 그대로
복제하지 말고 다음 디자인 특성만 적용한다. - 화면 전체를 덮는 딥
버건디/와인 톤의 배경 - 어두운 이미지 또는 추상적인 감성 비주얼 위에
반투명 버건디 오버레이 - 중앙 왼쪽에 큰 제목과 설명, CTA를 배치하는
히어로 구성 - 오른쪽에 주요 기능 또는 감성 키워드를 세로로 나열 -
아이보리색 본문과 핑크색 강조 포인트 - 상단에 간결한 브랜드 영역과
메뉴 - 하단에는 신뢰 문구 또는 짧은 서비스 안내

참고 이미지의 Magnific 로고, 브랜드명, 고유 카피, 인물 사진을 복사하거나
서비스가 제휴된 것처럼 표현하지 않는다. 별도 라이선스가 확인되지 않은
이미지 대신 CSS 그라데이션, 직접 제작한 추상 배경 또는 사용 권한이 있는
이미지를 사용한다.

## 2. 화면 구성

### 상단 내비게이션

-   좌측: 임시 텍스트 로고 `MOMENT`
-   우측: `서비스 소개`, `분석하기` 앵커 메뉴
-   로그인/회원가입 메뉴는 만들지 않는다.

### 히어로 영역

-   작은 안내 배지: `WORDS HAVE FEELINGS`
-   메인 제목 예시: `문장 속에 담긴\n감정을 읽다`
-   설명:
    `짧은 문장부터 긴 이야기까지, AI가 글의 감성 흐름을 분석해 드립니다.`
-   CTA: `감성 분석 시작하기`
-   오른쪽 기능 키워드: `긍정`, `부정`, `중립`, `감정의 이유`
-   화면 첫 진입 시 분석 영역으로 이동할 수 있는 CTA를 제공한다.

### 분석 영역

-   히어로 아래 또는 히어로 내부 하단에 배치한다.
-   제목: `오늘의 문장을 분석해 보세요`
-   다중 행 textarea
-   글자 수 `0 / 2,000`
-   저장 동의 체크박스 (기본 해제)
-   `감성 분석하기` 버튼
-   결과 영역은 처음에는 숨기거나 빈 상태 안내를 보여준다.

### 결과 영역

-   감성 라벨을 가장 먼저 보여준다.
-   신뢰도 퍼센트와 시각적 막대 표시
-   분석 이유 1\~3문장
-   모델 점수는 추정치임을 알리는 보조 문구
-   오류 발생 시 결과 대신 오류 안내를 표시한다.

### 하단

-   AI 분석은 참고 정보이며 사람의 감정을 확정하거나 진단하지 않는다는
    안내
-   간단한 저작권/서비스 표기

## 3. 디자인 토큰

CSS 변수로 관리한다. 아래 값은 초기 제안이며 한 파일에서 일관되게
조정한다.

``` css
:root {
  --color-bg: #210b16;
  --color-bg-deep: #160710;
  --color-panel: rgba(255, 240, 246, 0.08);
  --color-panel-border: rgba(255, 240, 246, 0.18);
  --color-text: #fff7fa;
  --color-muted: #d3b9c4;
  --color-accent: #ff4f9a;
  --color-accent-soft: #ff8fba;
  --color-positive: #8ed9b2;
  --color-negative: #ff8797;
  --color-neutral: #d6c4ed;
  --radius-card: 22px;
  --content-width: 1180px;
}
```

## 4. 타이포그래피와 간격

-   시스템 폰트 우선, 필요하면 라이선스가 명확한 웹폰트를 사용한다.
-   제목은 굵고 크게, 설명은 짧고 읽기 쉽게 한다.
-   본문 줄 간격은 1.5 이상을 권장한다.
-   카드와 입력 영역은 충분한 내부 여백을 둔다.
-   글자 크기·간격은 CSS 변수 또는 일관된 규칙으로 관리한다.

## 5. 반응형

-   데스크톱 1024px 이상: 히어로 2열 구성.
-   태블릿 768\~1023px: 콘텐츠 폭을 줄이고 2열 또는 세로 배치.
-   모바일 360\~767px: 한 열, 메뉴 간소화, 버튼 전체 폭, 입력창 전체 폭.
-   가로 스크롤이 생기지 않아야 한다.
-   `100vh`에만 의존하지 말고 모바일 브라우저 주소창을 고려한다.

## 6. 상호작용 상태

-   기본, hover, focus-visible, disabled, loading, success, error 상태를
    정의한다.
-   분석 중 버튼은 비활성화하고 `분석 중...`으로 표시한다.
-   결과 영역은 `aria-live="polite"`를 사용해 보조기기에 결과 변화를
    알린다.
-   색상만으로 감성 라벨을 구분하지 않고 텍스트 라벨과 아이콘/표식을
    함께 사용한다.

## 7. UI 완료 기준

-   첨부 이미지의 어두운 버건디·핑크·대형 히어로·기능 키워드 레이아웃을
    연상시키되 독자적인 브랜드 화면이어야 한다.
-   360px, 768px, 1440px 폭에서 레이아웃이 깨지지 않는다.
-   키보드만으로 메뉴, 입력, 체크박스, 분석 버튼을 사용할 수 있다.
-   입력·로딩·성공·오류 상태가 모두 시각적으로 구분된다.
